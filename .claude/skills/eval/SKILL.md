# /eval ── 読み取りの採点を回す

## いつ使うか
- 指示文（`src/reader.ts` の SYSTEM_PROMPT）やモデルの使い分け、家族設定の渡し方を変えたあと
- 1日の終わり（前後差を `docs/eval-history.md` に残す）

## 何をするか
1. 評価セットを集める
   - 公開：`eval/public/cases/*.json`（架空のお便り。画像は `eval/public/images/`）
   - 実物：`eval/private/cases/*.json`（あれば。**内容を画面に出さない・コミットしない**）
2. 各ケースを読み取り関数に通し、正解（`expected`）と突き合わせる
   - 実行：`npm run eval -- --set public` ／ `--set private` ／ `--set all`
   - 引数 `--tag <名前>` で、その回の名前を付ける（例：`p1-baseline`、`p1+family-facts`）
3. 10の観点で採点する（`eval/README.md` の表）。**⑨作らない は別に数え、0件でなければ赤で出す**
4. 結果を表にして報告し、`docs/eval-history.md` の末尾に1ブロック追記する
   - 書くのは：日付・tag・ケース数・観点ごとの正答率・全部合った割合・でっち上げ件数・何を変えたか1行
5. 落ちたケースは、`grader` サブエージェントに「どの観点が、なぜ外れたか」を1件ずつ見させる。直し案は `reviewer` に通してから採用

## 守ること
- 実物（`eval/private/`）の中身（子どもの名前・園名・写真）を、報告・ログ・コミットに出さない。番号と正誤だけ
- 正答率を上げるために正解側を書き換えない。正解を直すときは理由を `docs/journey.md` に書く
- 1回の `/eval` で指示文を変えるのは1か所まで（何が効いたか分かるように）
